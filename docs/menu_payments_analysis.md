# تحليل: الدفع عند الاستلام vs الفيزا + هيكل الأصناف

---

##第一部分: COD (Cash on Delivery) vs Card Payment

### واقع السوق في مصر والعالم العربي

```
نسبة الدفع عند الاستلام (COD) حسب السوق:
┌─────────────────────────────────────────────────────┐
│ مصر             │████████████████████████████  85%  │
│ السعودية        │██████████████████████        65%  │
│ الإمارات        │███████████████              45%  │
│ أوروبا/أمريكا   │███                          8%   │
└─────────────────────────────────────────────────────┘
```

في مصر: **85%+** من طلبات التوصيل تدفع كاش. هذا ليس رأياً، هذا واقع السوق.

---

### تحليل تأثير كل طريقة على العميل نفسه

لنأخذ عميل واحد اسمه **أحمد**، يطلب نفس الوجبة ($10) مرتين — مرة كاش ومرة فيزا:

#### السيناريو 1: أحمد يطلب بالفيزا

```
التطبيق → يختار الأكل → يضغط "ادفع" → يدخل بيانات card → 
يدفع (2-3% رسوم) → يوافق → الطلب يتجه للمطعم

التوصيل:
    - Rider يوصله → يسلم الطلب → خلاص. لا تفكير في الفكة.
    
قوة الفيزا هنا:
    - أحمد مش محتاج يفتكر يجيب فلوس كاش
    - السرعة: 30 ثانية عملية الدفع
    - لو الطلب غلط، سهل استرداد المبلغ (chargeback)
    
ضعف الفيزا هنا:
    - 2-3% رسوم على أحمد
    - أحمد ممكن يتردد في اللحظة الأخيرة قبل إدخال بيانات الكارت
    - لو الفيزا معلقة أو الرصيد ناقص → فشل الطلب → إحباط
    
سلوك أحمد:
    - يكمل الطلب? نعم بنسبة ~60% (40% بيترددوا وقت الدفع الإلكتروني)
    - بعد التوصيل: راضٍ، مادفعش كاش
    - التكرار: احتمال يرجع ياني تاني = 70%
```

#### السيناريو 2: أحمد يطلب كاش (COD)

```
التطبيق → يختار الأكل → يضغط "اطلب" → يختار "كاش" → 
لا يدخل بيانات دفع → الطلب يتجه للمطعم

التوصيل:
    - Rider يوصله → أحمد يدور في جيوبه على الفكة → 
    - "عندك فكة 200 جنيه?" → Rider يدور على الفكة
    - خلصت المعاناة → يسلم الفلوس
    
قوة الكاش:
    - أحمد أحسن بالثقة (مافيش卡信息 يتحرق)
    - نسبة إتمام الطلب أعلى (~90% يكملون بعد اختيار COD)
    - لو أحمد مش عنده银行卡، يقدر يطلب عادي
    
ضعف الكاش:
    - أحمد مش لاقي فكة → Rider ينتظر → تأخير
    - أحمد يفتكر إنه محتاج فلوس وهو خارج → يروح ATM
    - لو أحمد مش في البيت → الطلب يرجع → المطعم خسر
    - Rider معاه فلوس كتير → خطر أمني
    
سلوك أحمد:
    - يكمل الطلب? نعم بنسبة ~90% (لأن مفيش احتكاك في الدفع)
    - بعد التوصيل: عادي، دفع كاش
    - التكرار: احتمال يرجع ياني تاني = 55% (السبب: أحياناً مش لاقي فكة)
```

### المقارنة المباشرة

| المعيار | الكاش | الفيزا |
|---------|-------|--------|
| **معدل إتمام الطلب (Checkout Completion)** | ~90% | ~60% |
| **معدل رفض التوصيل (Delivery Rejection)** | 5-15% (مش لاقي فلوس/مش في البيت) | <1% |
| **سرعة عملية الدفع** | 30-60 ثانية (فكة) | 10-15 ثانية |
| **ثقة العميل** | عالية جداً | متوسطة (خوف على بيانات الكارت) |
| **الشريحة المستهدفة** | كل الناس (85%+ من السوق) | أصحاب الكروت فقط (30-40%) |
| **رسوم على العميل** | 0% | 2-3% |
| **رسوم على المنصة** | 0% | 2-5% (للمدفوعات الإلكترونية) |
| **مخاطر المنصة** | عالية (طلبات وهمية، رفض الاستلام) | منخفضة |
| **استرداد (Refund)** | صعب (فلوس كاش) | سهل (chargeback) |

### من "يكسب" من إيه؟

```
المنصة تكسب من الكاش ← أعلى نسبة طلبات → أعلى عمولة
المنصة تكسب من الفيزا ← نسبة أقل طلبات → لكن بيانات أفضل + استرداد سهل

الـ Rider:
    - كاش: خطر السرقة + معاناة الفكة
    - فيزا: أمان + لا فكة
    
المطعم:
    - كاش: يستلم فلوسه أسرع (Rider يدفعله كاش)
    - فيزا: يستلم بعد 3-7 أيام (تسوية بنكية)
    
العميل:
    - كاش: راحة نفسية + لا رسوم
    - فيزا: راحة جسدية (مافيش فكة) + سرعة
```

### استراتيجية زيادة COD بشكل ذكي (مش ضد بعض — مع بعض)

المبدأ: **COD هو سيد الموقف في مصر. حوله من نقطة ضعف لنقطة قوة.**

#### 1. COD مع تأمين (COD Secure)

```
بدل ما العميل يطلب كاش وخلاص ...

أحمد يختار "كاش" → الطلب ينزل → Rider يوصل 

المشكلة: 15% من طلبات COD بيرفضها العميل عند التوصيل

الحل: COD Secure
    → أحمد يدفع "تأمين" بسيط $0.5 عند الطلب (via InstaPay/Vodafone Cash)
    → التأمين بيترجعله بعد استلام الطلب
    → لو رفض الاستلام → التأمين يتخصم منه
    
النتيجة:
    - رفض التوصيل: 15% → 3%
    - العميل عنده حافز يستلم الطلب
    - المنصة تكسب: 50% من التأمين (ال 50% التانية تتعوض Rider)
```

#### 2. COD → Wallet (تحويل COD لمحفظة)

```
أحمد يطلب كاش $10 → Rider يوصل → أحمد يدفع $10 كاش

Rider يقول لأحمد:
    "حمل التطبيق، حول الـ $10 لمحفظتك، هتاخد $1 بونص على أول شحن"
    
النتيجة:
    - أحمد حمل التطبيق (أو فتحه)
    - أحمد شحن $10 في المحفظة
    - المرة الجاية: أحمد يدفع من المحفظة (بدون كاش)
    - المنصة: كسبت عميل loyal
```

#### 3. COD Gamification (نقاط + مشتريات مجانية)

```
أحمد يطلب كاش → يكسب XP زي ما هو
لكن لو دفعت بالفيزا → XP × 2 (ضعف النقاط)

—
أو بالعكس:
    أول 3 طلبات كاش: XP عادي
    الطلب الرابع كاش: XP × 3 (لكسر مقاومة الكاش)
    —
    كل 10 طلبات كاش: توصيلة مجانية
```

#### 4. COD Reminder (تذكير ذكي)

```
قبل التوصيل بـ 30 دقيقة:
    إشعار: "يا أحمد، طلبك هيوصل إن شاء الله. تأكد إن معاك $10 فكة 💪"

قبل التوصيل بـ 10 دقائق:
    واتساب/إشعار: "محتاج تحط $10 في محفظتك وندفع بدل الكاش?"
    (ودي طريق للتحويل لمحفظة)
```

#### 5. Partial COD (نصف كاش + نصففيزا)

```
الطلب $20:
    → $5 فيزا (تأمين الطلب)
    → $15 كاش (للاستلام)

الفوائد:
    - العميل يلتزم بالطلب (دفع $5)
    - لو رفض الاستلام → الشركة ما خسرتش ال $20 كاملة
    - العميل يجرب الدفع الإلكتروني خطوة بخطوة
```

#### 6. COD Fee Waiver (إلغاء رسوم COD)

```
الكثير من الشركات بتضيف $0.5-$1 رسوم COD.

الاستراتيجية: 
    - إلغاء رسوم COD بالكامل
    - بدالها: "اطلب كاش، اكسب نقاط، استبدلها بتوصيل مجاني"
    
النتيجة:
    - العميل سعيد (مدفوعش زيادة)
    - المنصة كسبت بيانات + loyalty
```

## الجزء الثاني: هيكل الأصناف (Menu Structure)

### المشكلة

في Faster القديم: الخدمة = "سباك" أو "كهربائي" (service واحد بسيط)
في التوصيل: المطعم عنده قائمة معقدة: أصناف، أحجام، إضافات، تشكيلات، عروض، باكيدجز...

نحتاج **نموذج بيانات قوي** يتحمل تعقيد المنيو.

---

### تحليل كل عنصر

#### 1. 🥘 الصنف (Item)

أبسط وحدة: "بيتزا مارجريتا" أو "برجر دبل تشيز"

```
Item:
    - id
    - restaurant_id
    - name / name_ar
    - description / description_ar
    - base_price (السعر الأساسي)
    - image_url
    - is_available
    - prep_time (دقائق)
    - calories, fat, protein (optional — nutritional info)
    - dietary_tags: [vegetarian, vegan, gluten_free, spicy]
    - sort_order
    - is_best_seller / is_new / is_chef_special
```

**سلوك العميل:** يدخل المطعم → يشوف الأصناف → يضغط على واحد → يشوف التفاصيل → يضيف للسلة

---

#### 2. 📏 الاختلافات (Variations / Sizes)

نفس الصنف بأحجام وأسعار مختلفة:
- "بيتزا مارجريتا" = Small $5 / Medium $8 / Large $11

```
Variation:
    - id
    - item_id
    - name / name_ar (Small / Medium / Large)
    - price_adjustment (الفرق عن base_price)
    - is_default
```

**في السلة:** العميل اختار "بيتزا مارجريتا + Large"

---

#### 3. ➕ الإضافات (Add-ons / Extras)

إضافات optional للسعر:
- جبنة إضافية +$1.5
- مشروم +$1
- بيبروني +$2

```
Addon:
    - id
    - item_id
    - name / name_ar
    - price
    - max_quantity (العميل يقدر يضيف كام قطعة؟)
```

**في السلة:** بيتزا مارجريتا Large + جبنة إضافية × 2 + مشروم × 1

---

#### 4. 🔄 الخيارات الإجبارية (Required Choices / Modifiers)

"البرجر: عايزه مع رز ولا بطاطس؟" (اختيار إجباري)

```
ModifierGroup:
    - id
    - item_id
    - name / name_ar
    - type: 'single' (اختيار واحد) | 'multi' (اختيار متعدد)
    - is_required: true/false
    - min_selections: 1
    - max_selections: 1

ModifierChoice:
    - id
    - modifier_group_id
    - name / name_ar
    - price_adjustment
    - is_default
```

**مثال:**
```
ModifierGroup: "Side" (required, single)
    ├── Fries — $0
    ├── Rice — $0
    └── Salad — +$1

ModifierGroup: "Drink" (optional, single)
    ├── Coke — +$2
    └── Water — +$1
```

**في السلة:** برجر دبل تشيز + Side: Fries + Drink: Coke

---

#### 5. 📦 الباكيدجز / الوجبات (Packages / Combos / Meals)

مجموعة أصناف بسعر مخفض:
- "وجبة برجر" = برجر + بطاطس + مشروب = $8 (بدلاً من $11 لو منفردين)

```
Combo:
    - id
    - restaurant_id
    - name / name_ar
    - description
    - image_url
    - combo_price (السعر الإجمالي للمجموعة)
    - is_available
    - valid_from / valid_to (للوجبات الموسمية)

ComboItem:
    - id
    - combo_id
    - modifier_group_id (المرتبط ب item داخل ال combo)
    -- مثلاً: الوجبة تشمل 1 برجر + 1 side + 1 drink
    
ComboModifierRule:
    - id
    - combo_item_id
    - 선택 규칙
    -- مثلاً: في الوجبة، تختار side من (Fries, Rice, Salad) بس مش مضطر تدفع زيادة
```

**مثال وجبة (Combo):**
```
وجبة "Double Cheese Meal" — $8.50
    ├── أي برجر من قائمة البرجر (اختيار واحد)
    ├── أيサイド من Fries/Rice/Salad (اختيار واحد)
    └── أي مشروب من Coke/Sprite/Water (اختيار واحد)

توفير: $3 عن شرائهم منفردين
```

---

#### 6. 🏷️ العروض (Offers / Promotions)

عروض من المطعم أو المنصة:

```
Promotion:
    - id
    - restaurant_id (null = platform-wide)
    - type: 'percent' | 'fixed' | 'free_item' | 'free_delivery' | 'bogo'
    - value: 20 (% أو $)
    - code: "YALLA50" (nullable — للعروض بكود)
    - min_order_amount: $10
    - max_discount: $5
    - usage_limit: 1000
    - used_count: 0
    - valid_from / valid_until
    - is_active
    - target_user_type: 'all' | 'new' | 'returning'
```

#### 7. 💥 العروض الخاطفة (Flash Sales)

عرض بكمية محدودة ووقت محدد:
```
FlashSale:
    - id
    - item_id (أو combo_id)
    - discount_price
    - quantity_limit
    - sold_count
    - expires_at (وقت محدد — 3 ساعات مثلاً)
    - is_active
```

**سلوك Gen Z:** "عرض خاطف — باقي 15 دقيقة و 10 قطع فقط!" → FOMO → يشتري فوراً

---

#### 8. 🔀 التشكيلات (Formations / Set Meals)

"تشكيلة العائلة" أو "طبق اليوم" — عبارة عن باكيچ متكامل:

```
Formation:
    - id
    - restaurant_id
    - name / name_ar ("تشكيلة العائلة", "طبق اليوم")
    - description
    - total_price
    - image_url
    - available_from / available_to (لـ "طبق اليوم" مثلاً)
    - is_active

FormationSlot:
    - id
    - formation_id
    - slot_label: "اختر المقبلات" | "اختر الطبق الرئيسي" | "اختر الحلو"
    - slot_type: 'item' | 'combo'
    - min_selections: 1
    - max_selections: 1
```

**مثال تشكيلة "طبق اليوم" (Chef's Special):**
```
طبق اليوم الاثنين — $12
    ├── شوربة العدس (مقدمة — اختياري)
    ├── ريزوتو الفطر (طبق رئيسي — إجباري)
    └── تشيز كيك (حلو — اختياري)
    
العميل يقدر يختار: 
    - شوربة + ريزوتو + تشيز كيك = $12
    - أو ريزوتو بس = $8
    - أو ريزوتو + تشيز كيك = $10
```

---

#### 9. 🏪 تصنيفات القائمة (Menu Categories)

تجميع الأصناف في أقسام:

```
MenuCategory:
    - id
    - restaurant_id
    - name / name_ar ("مقبلات", "مشاوي", "مشروبات")
    - description
    - image_url (optional — banner للقسم)
    - sort_order
    - is_available
```

---

#### 10. 🏷️ التاجات والفلترة (Tags & Filters)

```
Tag:
    - id
    - name / name_ar ("حار", "نباتي", "مناسب للدايت")
    - icon_url

ItemTag:
    - item_id
    - tag_id
```

**استخدام Gen Z:** يفتح الفلتر → "عاوز حاجة نباتي" → الأصناف النباتية تظهر

---

#### 11. ⭐ التقييمات على مستوى الأصناف

مش بس تقييم المطعم ككل — تقييم كل صنف على حدة:

```
ItemReview:
    - id
    - item_id
    - customer_id
    - order_id
    - rating (1-5)
    - comment
    - image_url (optional — صورة الطبق)
    - created_at
```

"البيتزا مارجريتا عندهم 4.8 ⭐ — لازم أجربها"
"البرجر نجمتين — مش أحسن حاجة"

---

### 12. 🛒 السلة الذكية (Smart Cart)

السلة مش مجرد تخزين مؤقت — السلة **ذكية**:

```
CartItem:
    - id
    - customer_id
    - restaurant_id
    - item_id
    - variation_id (لو اختار Size)
    - quantity
    - special_instructions: "من غير بصل"
    - addons: [{"addon_id": 1, "quantity": 2}, {"addon_id": 3, "quantity": 1}]
    - modifiers: [{"modifier_group_id": 1, "choice_id": 2}, ...]
    - item_total_price (محسوب)
    - combo_id (لو جاي من باكيچ)
    - formation_id (لو جاي من تشكيلة)
    - saved_for_later: false
    - created_at
```

**سلوك السلة الذكية:**

```
1. العميل يضيف "بيتزا مارجريتا Large"
    → السلة تقترح: "عاوز تجيب معاها مشروب? اضافة Coke ب $2 بس"
    
2. العميل يضيف "برجر"
    → السلة تقترح: "حولها لوجبة برجر + بطاطس + مشروب ووفر $3"

3. العميل يوصل لـ $15
    → السلة تقترح: "عندك 3$ زيادة عشان توصل للطلب المجاني $18!"
    
4. العميل يضيف صنف من مطعم تاني
    → السلة تخلق طلب منفصل (لأن المطعم مختلف)
```

### نموذج البيانات المتكامل (Data Model)

```
Restaurant
    ├── MenuCategory (1:N) — "مقبلات", "رئيسي", "مشروبات"
    │     └── Item (1:N)
    │           ├── Variation (1:N) — Small $5 / Medium $8
    │           ├── AddonGroup (1:N) — "إضافات"
    │           │     └── Addon (1:N) — جبنة $1.5, مشروم $1
    │           ├── ModifierGroup (1:N) — "اخترSide"
    │           │     └── ModifierChoice (1:N) — Fries $0, Rice $0
    │           └── Tag (N:N) — حار, نباتي, دايت
    │
    ├── Combo (1:N) — "وجبة برجر" $8.50
    │     ├── ComboItem (1:N) — برجر (main), Side, Drink
    │     └── ComboModifierRule — كل item اختيار من group
    │
    ├── Formation (1:N) — "طبق اليوم", "تشكيلة العائلة"
    │     └── FormationSlot (1:N) — slot: اختيار مقبلات
    │
    ├── Promotion (1:N) — خصم 20%, BOGO, توصيل مجاني
    ├── FlashSale (1:N) — عرض خاطف 3 ساعات
    │
    └── ItemReview (1:N) — تقييم كل صنف
```

### كيف يتصرف كل عنصر مع العميل؟

| العنصر | شوفه العميل فين؟ | إيه اللي يخلقه يشتري؟ |
|--------|------------------|---------------------|
| **Item** | قائمة المطعم الأساسية | صورته وسعره وتقييمه |
| **Variation** | تحت كل صنف — اختيار حجم | السعر المناسب لاحتياجه |
| **Addon** | تحت الصنف — إضافات اختيارية | "جرب إضافة جبنة" |
| **Modifier** | تحت الصنف — خيارات إجبارية | لازم يختار عشان يكمل |
| **Combo** | قسم "الوجبات" في المطعم | التوفير ($3 أقل) |
| **Formation** | قسم "تشكيلات اليوم" | التجربة الجديدة |
| **Promotion** | الرئيسية أو فوق القائمة | "خصم 20% أول طلب" |
| **Flash Sale** | عد تنازلي — FOMO | "باقي 10 دقايق!" |
| **Tag** | فلتر الأصناف | "عاوز نباتي" |
| **ItemReview** | تحت كل صنف | "4.8 ⭐ — جربته!" |

### الـ "سوبر باور" لـ Gen Z

1. **Build Your Own** — اختار المكونات بنفسك (مثل Build-a-Bear بس للأكل)
2. **Surprise Meal** — "فاجئني" — التطبيق يجيبلك حاجة عشوائية حسب مزاجك (تمشياً مع Mood Discovery)
3. **Mood-Based Menu** — "مزاجي حلويات" → يظهر له الحلويات فقط
4. **Visual Menu** — قائمة مصورة بالكامل (صور جريئة Neubrutalism)
5. **Price Slider** — "أقل من $5" → يظهر الأصناف اللي تحت $5
6. **Social Proof** — "15 واحد طلبوا النهارده" تحت كل صنف
7. **Combo Creator** — اسحب وارمي مكونات الوجبة بنفسك (drag & drop)

---

الخلاصة: 

- **COD** هو الأساس في مصر (85%+). لا تحاربه — طوره (Secure Deposit, تذكير فكة, تحويل لمحفظة, نقاط)
- **الهيكل الهرمي للمنيو**: Restaurant → MenuCategory → Item → Variation/Modifier/Addon → Cart
- **Combo و Formation** يزيدان متوسط قيمة الطلب (AOV) بنسبة 20-35%
- **Flash Sales** تخلق FOMO لجذب Gen Z
- **التقييمات على مستوى الصنف** تزيد الثقة بنسبة 40%
